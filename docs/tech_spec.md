# Техническое задание (ТЗ) для школьного проекта

## 1. Название проекта
**MarkoBot — бот для учета запросов дополнительного времени и согласований**.

---

## 2. Цели проекта
1. Упростить процесс запроса дополнительного времени на телефоне у ребенка.
2. Ввести автоматический учет лимитов (по времени и количеству запросов).
3. Обеспечить прозрачность для родителей через отчеты.

---

## 3. Описание проблемы
Семья использует родительский контроль (Google Family Link / Kaspersky Safe Kids). Ребенок регулярно просит добавить время или разрешить приложение. Сейчас это делается вручную и не всегда прозрачно (сколько времени уже было добавлено, сколько запросов было в день).

---

## 4. Задачи проекта
1. Бот принимает запросы от ребенка.
2. Проверяет лимиты.
3. Отправляет запрос родителям на подтверждение.
4. Ведет учет разрешенного времени и количества запросов.
5. Формирует ежедневный отчет.

---

## 5. Пользователи и роли
- **Ребенок** — делает запросы.
- **Родитель** — подтверждает или отклоняет.

---

## 6. Функциональные требования
### 6.1 Запрос времени
- Ребенок может запросить 15/30/60 минут.
- Бот проверяет лимит:
  - не более 5 запросов в день;
  - не более 180 минут суммарно в день.
- При превышении лимита бот отказывает.

### 6.2 Запрос приложения
- Ребенок может отправить запрос на установку или запуск приложения.
- Родителям приходит уведомление с кнопками «Разрешить» / «Отклонить».

### 6.3 Ежедневный отчет
- В 21:00 бот отправляет родителям отчет:
  - сколько запросов было,
  - сколько минут было разрешено,
  - сколько отклонено.

---

## 7. Нефункциональные требования
- Простой интерфейс (кнопки, понятные команды).
- Хранение данных (SQLite в MVP, PostgreSQL в будущем).
- Стабильность работы 24/7.
- Возможность расширения на несколько семей.

---

## 8. Ограничения
- Нет официального публичного API у Google Family Link / Kaspersky Safe Kids.
- Поэтому в MVP интеграция ручная (бот отправляет инструкцию родителям).

---

## 9. Архитектура (MVP)
### 9.1 Компоненты
- **Telegram-бот** (интерфейс для ребенка и родителей).
- **Сервис логики** (лимиты, учет запросов).
- **База данных** (SQLite).

### 9.2 Потоки данных
1. Ребенок отправляет запрос.
2. Бот проверяет лимиты.
3. Родителям приходит запрос на подтверждение.
4. Родители подтверждают.
5. Бот сохраняет результат.

---

## 10. Технологии
- Python 3.11
- aiogram (Telegram Bot API)
- SQLite (MVP)
- Docker (деплой)

---

## 11. План этапов
### Этап 1 — MVP (4 недели)
- Команды и меню.
- Лимиты.
- Уведомления родителям.
- Ежедневный отчет.

### Этап 2 — Beta (1–2 месяца)
- Роли пользователей.
- PostgreSQL.
- Логирование.

### Этап 3 — Подготовка к прод
- Контейнеризация.
- CI/CD pipeline.
- Мониторинг.

---

## 12. Критерии приемки
1. Бот отвечает на запросы.
2. Лимиты работают корректно.
3. Родители получают уведомления.
4. Отчет приходит ежедневно.
5. Данные сохраняются между перезапусками.
